# 23. 显式分页 vs 滚动分页

> 「分页是显式分页比较好，还是滚动分页比较好」——这篇是定案。

## 结论：**显式分页**（页码 + 上一页/下一页）

判断依据是**这个应用的使用场景**，不是通用偏好：

| 维度 | 显式分页 | 滚动/加载更多 |
|---|---|---|
| 遥控器跳页 | ✅ PgUp/PgDn 直接跳 | ❌ 只能一页页往下加 |
| DOM 规模 | 固定 50 行 | 加载到 500 条会明显变卡 |
| "我在第几页" | ✅ 有反馈 | ❌ 只有"已显示 N 首" |
| 回到前面 | ✅ 点页码 | ❌ 得一路往回滚 |
| 无限流（67 万首） | 页码没意义 | ✅ 更自然 |

**关键判断：KTV 的列表都是有界的。**

- 搜索结果：几十条（1~3 页）
- 歌手名下歌曲：几十条
- 已唱 / 收藏 / 歌单：几百条
- 热歌榜：理论无限，但没人靠翻页浏览 67 万首 —— **都是搜索**

所以"无限流"这个唯一优势在 KTV 场景里不成立，而显式分页的三个优势全中。

## 实现

### 曲库侧（`CatalogBrowser.vue`）

翻页时**整页替换**，不再往数组后面追加：

```js
async function loadHot(pageNo = 1) {
  page.value = pageNo
  const r = await bridge.catalog.hot({ limit: PAGE, offset: (pageNo - 1) * PAGE })
  songs.value = r.songs        // ← 替换，不是 [...songs, ...r.songs]
  hasMore.value = r.hasMore
  scrollListTop()              // 翻页后回到顶部
}
```

分页条吸底常驻：

```
[‹ 上一页]   第 2 页   [下一页 ›]
```

**不知道总页数**（`COUNT(*)` 在 67 万行上要 3.9 秒，不能每次搜索都算），
所以只显示当前页码，"下一页"按 `hasMore` 禁用。

### 已唱 / 收藏 / 歌单（`QueuePanel.vue`）

这几个**知道总数**（就是数组长度），所以显示完整信息：

```
[‹ 上一页]  第 2 / 5 页 · 共 213 条  [下一页 ›]
```

## 键盘 / 遥控器

| 按键 | 作用 |
|---|---|
| `↑` / `↓` | 移动选中项 |
| `Home` / `End` | 跳到列表首 / 尾 |
| **`PageUp` / `PageDown`** | **上一页 / 下一页** |
| `Enter` | 对选中项执行默认动作 |

这就是选显式分页的直接收益：遥控器按一下 PgDn 就翻页，
不用"滚到底 → 加载 → 再滚到底 → 再加载"。

## 一个必须注意的状态坑

`page` 和 `hasMore` 都是**跨标签共享**的状态。切标签时必须一起重置，
否则从热歌榜（有下一页）切到「本地文件」（只有 13 首）会显示一个点了没反应的"下一页"。

```js
function switchTab(id) {
  page.value = 1
  hasMore.value = false
  ...
}
```

队列面板同理，另外还要防"删到不足一页时停在空白页"：

```js
watch([currentRows, totalPages], () => {
  if (page.value > totalPages.value) page.value = totalPages.value
})
```

## 补充：每页条数可选 + 直接跳页

### 每页条数

分页条左侧有 **每页 [20/30/50/100] 条** 的下拉，改完回到第 1 页。
选择会写进设置（`pageSize`），下次启动保持。

> 为什么改每页条数要回第 1 页：页码是"第几个 30 条"，条数一变换算就失去意义了。

### 跳页

页码本身就是一个**输入框** —— 点进去输数字回车即可跳：

```
每页 [30] 条   ‹   第 [7] 页   ›
```

这样翻到第 20 页不用点 19 次「下一页」。

已唱 / 收藏 / 歌单还多两个按钮（因为它们知道总页数）：

```
每页 [30] 条  «  ‹  第 [2] / 5 页  ›  »
```

非法输入（0、负数、非数字）会**还原成当前页码**，不会跳到空白页。
队列面板还会把输入值**夹到总页数内**。

## 顺带做的三条样式优化

### 1. 标签徽标更清晰

原来只是"一点底色"，深色主题下几乎看不见。改成**胶囊徽标**：

- 常态：`#33465c` 底 + 亮字
- 选中态：主题绿底 + 深色字 + 加粗

### 2. 窄栏收起「下首」

歌曲行右侧原本是 `已点 + ♡ + 下首`，在 430px 以下的容器里会把歌名挤没。
现在窄栏下**只收起「下首」**（右键菜单里还有同一项），歌名优先。

### 3. 歌词空行改成呼吸点

纯音乐段落没有歌词行时，原来显示一个孤零零的「…」。
现在换成**三个依次呼吸的圆点**（`@keyframes` 错开 0.2s），更像"正在等下一句"。
