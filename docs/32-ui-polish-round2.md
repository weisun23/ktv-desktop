# 32 · 界面第二轮整体优化（控制条 / 设置页 / 大屏模式）

用户要求“从页面样式入手，继续优化，能做的都做”。本轮不改播放链路，
只处理页面层级、操作精度和大屏可用性。

---

## 1. 控制条改成响应式两行

### 问题

之前所有控件都在一行里抢宽度。实测 1180 窗口下：

- 控制条总宽约 730px；
- 进度条只有约 167px；
- 原伴唱、变调、音量都要靠压缩按钮和滑块才能放下。

### 改法

控制条改成 CSS Grid：

- 宽窗口（w0/w1）：歌名 / 进度 / 播放 / 原伴唱 / 变调 / 音量保持单行。
- 窄窗口（w2）：进度条独占第一行，其余操作放第二行。
- 最窄窗口（w3）：再隐藏变调和全屏，但播放、切歌、快进快退、原伴唱、音量始终保留。

这样拖动进度条不再需要盯着 100 多像素的细线，窄窗口也不靠隐藏核心功能硬塞。

---

## 2. 设置页改成左导航 + 搜索

原来设置弹窗里 10 个分组全部纵向滚动，找到“音频分离”或“手机点歌”要滚很久。

现在：

- 弹窗宽度从 720px 扩到 900px 级别；
- 左侧固定分组导航：播放与画面 / 播放行为 / 界面主题 / 播放诊断 / 数据源 / 数据位置 / 缓存 / 手机点歌 / 曲库更新 / 音频分离；
- 顶部有“搜索设置”输入框，支持按中文标签和关键词过滤；
- 右侧内容区只显示当前分组；
- 底部关闭按钮固定，不需要滚到底。

---

## 3. 显示密度：自动 / 舒适 / 大屏

设置页新增显示密度：

| 模式 | 行为 |
|---|---|
| 自动 | 窗口达到 1600px 时自动放大行高和部分按钮 |
| 舒适 | 保持当前桌面尺寸 |
| 大屏 / 遥控器 | 强制放大歌曲行、歌手卡、队列行、A-Z 索引和分页按钮 |

密度同时写入设置文件和 localStorage，启动挂载前先贴到 `<html data-density>`，避免先渲染小字号再跳大。

---

## 4. 右栏可拖拽调宽

左画面和右栏之间增加拖拽分隔线：

- 范围约 340–620px；
- 拖动时高亮主色；
- 双击恢复自动宽度；
- 宽度写入设置，下次启动保持；
- 视频区继续由 ResizeObserver 重新上报原生窗口位置。

右栏宽度变化后，歌手页网格会自动从两列变三列或更多列。

---

## 5. 正在播放条

右栏顶部增加一条正在播放状态：

- 播放状态点；
- 歌名 / 歌手；
- 当前时间 / 总时长；
- 原唱 / 伴唱快捷切换；
- 底部细进度线。

切到已点、已唱、收藏、歌单时仍能看到当前播放内容，不用回到曲库。

---

## 6. 骨架屏和空态

- 曲库加载中改为 7 行骨架屏，不再只显示“加载中…”；
- 无结果显示带图标的空态卡片，提示换关键词或切换数据源；
- 封面缺失继续使用名字渐变色 + 首字。

---

## 7. 主题和顶栏细节

- 新增两套主题：
  - 舞台霓虹：深紫黑 + 紫红主色；
  - 翡翠：深墨绿 + 翡翠绿。
- 数据源切换按钮加图标；
- 缓存统计改成胶囊；
- 顶栏底部增加当前播放进度细线。
