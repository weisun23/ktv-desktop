# 视频区遮挡、全屏按钮、卡顿排查

**日期**：2026-09-22

## 1. 播放页遮挡右侧列表 ✅ 已修

### 根因

原生视频子窗口的宽度算错了，压到了右栏上。实测数据：

```
视频区 rect (CSS) = { x: 12, w: 794 }   右边缘 = 806
右栏起点 (CSS)    = 794                 ← 视频区比应得的宽度多了 24px
```

24px 正好是 `.main` 的 padding。原因是 `.left` 只写了 `grid-template-rows`，
**没有显式写 `grid-template-columns`**，隐式列是 `auto`，会被内容撑宽。

修法：

```css
.left {
  display: grid;
  grid-template-columns: minmax(0, 1fr);   /* ← 关键：给列一个可收缩的下限 */
  grid-template-rows: 1fr auto auto;
}
```

修复后实测：视频区 770px（原 794），右边缘 1173 物理像素 < 右栏起点 1191，**不再重叠**。

> 这类"隐式 grid 列被内容撑宽"的问题在别处也要注意——凡是 grid 容器，
> 子项需要收缩时都要显式写 `minmax(0, 1fr)`。

## 2. 全屏按钮 ✅ 已加

控制条上新增「全屏」按钮（快捷键 `F`，`Esc` 退出）。

全屏时：

- 顶栏、右栏、歌词都隐藏，画面铺满整个窗口

## 3. 卡顿：仍然复现不了，但做了两件事

### 3.1 又加了一层验证

之前测的是"隐藏窗口 + 空页面"，这次补上了**真实场景**：
可见窗口 + 加载完整前端 + 原生子窗口。

```
=== 真实场景（可见窗口 + 完整界面 + 子窗口）===
时间轴推进: 19.9s / 20.0s => 1.00x
真停顿(>600ms): 0   最长: 302ms
判定: 流畅
```

**仍然流畅。** 到这里已经覆盖了：顶层窗口 / 子窗口 / 并发下载 / 大缓存 / Electron 内 / 真实界面，
全部流畅。

### 3.2 试了用 libVLC 统计做硬证据，但接口不对

想读 `i_lost_pictures`（丢帧数）作为卡顿的硬指标，结果：

```
Cannot find function 'libvlc_media_player_get_stats' in shared library
```

**libVLC 3 移除了这个接口**，改成了 `libvlc_media_get_stats`（挂在 media 上）。
改过来后 koffi 的 out 参数仍取不到值（返回码非 0）。这条路暂时搁置——
丢帧统计是"锦上添花的诊断"，不是修复本身。

### 3.3 降低了后台缓存对播放的影响

这是我能想到的、**你那边与我不同的唯一变量**——我的网速快（34MB 约 4 秒），
下载抢带宽的影响看不出来；你的网络慢的话，后台缓存可能把播放饿死。

两处调整：

| 项 | 原 | 现 |
|---|---|---|
| 缓存限速默认值 | 1 MB/s | **512 KB/s** |
| 缓存时机 | 只能"播放时也缓存" | 新增**「仅空闲时缓存」**选项 |

设置页「缓存」分组里可以切换。**播放时卡顿就选「仅空闲时」**——完全不和播放抢带宽。

## 5. 仍然待确认

**卡顿到底是不是带宽问题，需要你试一下**：

1. 打开设置 →「缓存」→ 选**「仅空闲时」**
2. 再播一首歌看看

如果还卡，请告诉我：

- 你的宽带大概多少 M
- 卡的时候**画面卡还是声音也断**（声音也断更像网络/带宽）
- 卡是**一直卡**还是**播一会儿才卡**
- 右上角「已缓存」的数字在不在涨（涨说明下载在跑）
