# 19. 逐字歌词（卡拉OK字幕）

> 之前歌词只有"整行高亮"。这篇讲怎么做到**逐字扫色**，以及为什么绕了一圈。

## 结论

**用 ASS 字幕的 `\k` 卡拉OK标签，而不是 mpv 的 OSD。**

```
[20100,2030](20100,440,0)阴(20540,690,0)天 (21230,260,0)在...
        ↓ 编译成
Dialogue: 0,0:00:20.10,0:00:22.13,KTV,,0,0,0,,{\k44}阴{\k69}天 {\k26}在...
```

样式里 `PrimaryColour` = 已唱色、`SecondaryColour` = 未唱色，
播放器自己按 `\k` 的厘秒数一个字一个字扫过去。

实测（差分对比，同帧有/无字幕）：**已唱部分绿色、未唱部分白色**，正确。

## 数据来源：网易云 yrc

只有 **v1 接口**带逐字数据（老接口只有逐行）：

```
GET /api/song/lyric/v1?id=<id>&lv=-1&kv=-1&tv=-1&rv=-1&yv=-1&ytv=-1&yrv=-1
    -> { lrc: {...逐行...}, yrc: { lyric: "<NDJSON + YRC>" } }
```

`yrc.lyric` 是**两种格式混在一起**的：

```
{"t":0,"c":[{"tx":"作词: "},{"tx":"李宗盛"}]}          ← JSON 元数据行（跳过）
[221970,6800](221970,300,0)傻(222270,250,0)傻...      ← YRC 正文行
```

YRC 正文行的结构是：

```
[行起始ms,行时长ms](字起始ms,字时长ms,0)字(字起始ms,字时长ms,0)字...
```

**坑**：`(t,d,0)` 后面跟到下一个 `(` 之前的所有字符都属于这个字，
所以一个字可能是**空格**（比如 `人 `），按固定宽度切会全错位。

## 为什么不用 mpv 的 OSD

一开始想在 `osd-msg1` 里塞 ASS 覆盖码，实测三种写法全不行：

| 写法 | 结果 |
|---|---|
| `{\b1}粗体{\b0}普通` | 原样显示 `{\b1}粗体{\b0}普通`（`{}` 不解析） |
| `{\c&H00FF00&}绿` | 显示 `(broken escape sequences)` |
| `{\1c&H00FF00&}绿` | 同上 |

`osd-ass-cc` 是**只读属性**不是启动选项（写成 `--osd-ass-cc=yes` 会让 mpv 直接退出，exit=1）。

而 **ASS 字幕**本来就支持 `\k`，mpv 也完整支持 ASS 渲染 —— 所以改走字幕。

## 三层回退

不是每首歌都有逐字数据，所以：

```
有逐字数据 + mpv 内核  ->  ASS 卡拉OK字幕（画面里逐字扫色）
有逐行数据             ->  osd-msg1 逐行显示（原来的行为）
都没有                 ->  什么都不显示
```

**两者互斥**：挂上 ASS 字幕时会把 OSD 文本清空，否则画面上会出现两行歌词
（`assLyricsActive` 这个标志就是干这个的）。

## 老缓存自动升级

早期版本只缓存了 `.lrc`，连网易云 id 都没记。所以缓存命中但没有逐字数据时：

1. 有 `.lyric-meta.json` 就直接按里面的 id 拉一次 yrc
2. 没有 meta 就重新搜一次拿到 id
3. 补到逐字数据后写缓存，并回调 `lyrics.onWordsReady` ——
   如果正好是当前这首歌，立刻把卡拉OK字幕挂上去（不用重新点歌）

全程后台进行，不阻塞歌词显示。

## 底部歌词条也支持逐字

「只显示底部条」模式下，`LyricsBar.vue` 用同一份 `words` 渲染：
已唱绿 / 正在唱亮白带辉光 / 未唱灰。

- `apps/shell/src/lyrics.js` — `parseYrc()` + v1 接口 + 逐字缓存 + 后台回填

## 附录 3：歌词重复显示 + 设置不生效（2026-09 修）

### 问题 1：同一句歌词上下各显示一遍

`state.js` 里有两个**独立开关**：

```js
lyricsOnVideo: true,   // 画在视频画面里
showLyrics: true,      // 画面下方的歌词条
```

两个默认都是 `true`，所以歌词**同时出现在画面里和画面下方**。
而设置页写的是「画在视频里 / **只显示底部条**」—— 这个措辞暗示了
"画在视频里时底部条不显示"，但实际并没有。用户看到两行歌词只会以为是 bug。

**修法**：

1. `showLyrics` 默认改成 `false` —— 只画在视频里，不叠一份
2. 设置页把「位置二选一」改成**两个独立开关 + 一个"都关"**，并写清关系：

   ```
   歌词显示   [画面内 ✓] [底部条] [都关]
   提示：两个是独立开关，可以只开一个、都开、都关。
        默认只开「画面内」——MV 往往自带歌词，底下再叠一条会重复。
   ```

3. 控制条上的「词」按钮保留 —— 想临时看底部条随时点开

> 注意 `LyricsBar` 用的是 `v-show`（不是 `v-if`），所以底部条隐藏时组件仍然挂载，
> **仍然会把当前行喂给画面字幕**。这正是我们要的：关掉底部条不影响画面歌词。

### 问题 2：设置页改了歌词开关要重启才生效

`App.vue` 里：

```html
<SettingsDialog @changed="refreshFavorites(); refreshCounts()" />
```

只刷新了收藏和计数 —— **歌词开关没有同步回本地 ref**。
用户在设置里点「底部条」，界面上什么都不会变，直到重启应用。

修法：加 `onSettingsChanged()`，把两个开关读回本地 ref，
并且**立刻重挂一次画面歌词**（`lastVideoLine = null` 后重发当前行），
这样"画面内"开关也是即时生效的。

### 教训

**两个语义重叠的开关，默认值一定要互斥。** 否则用户看到的是
"两个功能同时生效"，而每个开关单独看文档都是对的。
