# 30 · 整体界面评审（分页条位置 + 布局瘦身）

用户反馈："分页条显示的位置不合理，另外从整体页面分析下还应该怎么优化"。
下面是逐项量过的结果。

---

## 一、分页条：之前是**压在列表上**的

### 问题

`.pager` 原来是 `.list`（滚动容器）里的 `position: sticky; bottom: 0`，
底还是 `linear-gradient(to top, var(--bg) 72%, transparent)` —— 半透明。

实测（窗口 1266×763）：

```
.list     高度 377   scrollHeight 1959（30 条）
.pager    top=581  高 47   position=sticky
第 6 条歌  top=580   ← 正好被分页条盖住
```

也就是说：**列表最后一行永远被分页条压着**，而且因为底是半透明的，
还能看到半截字。这就是"位置不合理"。

### 修法

把分页条**移出滚动区**，和左边那行图例合并成一条固定在面板底部的工具条：

```html
<div class="list">…</div>          <!-- 只有它在滚 -->
<div class="bottombar">
  <div class="legend">● 本地 ● 在线 ● 不可播</div>
  <div class="pager">每页 [30] ‹ [1] ›</div>
</div>
```

`QueuePanel`（已点/已唱/收藏/歌单）里同样的问题、同样的改法。

### 效果

| | 之前 | 现在 |
|---|---|---|
| 分页条 | sticky 压在列表上（盖住 47px） | 独立底栏，不遮任何内容 |
| 图例 | 单独一行 31px | 并进底栏（省 31px） |
| 状态行 | 常驻 22px | **只在出问题时显示**（省 22px） |
| 数据源切换 | 48px | 44px（边距收紧） |
| **列表可用高度** | **≈330px**（377 − 47 被盖） | **396px** |

列表可用高度 **+20%**，一屏从 5 行变 7 行。

## 二、顺手发现并修掉的问题

### 1. 空闲时视频区是纯黑，占位提示出不来

```js
// 之前
const hasMedia = computed(() => !!status.value.filePath)
```

队列放完之后主进程会 `player.stop()`，但**不会清掉 `filePath`** ——
于是 `hasMedia` 一直为真，原生视频窗口继续盖着（一片黑），
`VideoStage` 里那句"请点歌"的占位提示**永远出不来**。

改成用 `status.song` 判断（队列空了主进程会把它置空），
顺便把占位文案改对了（"从右侧曲库点一首歌"，之前写的是 libVLC）。

### 2. "热歌榜"标题重复

页签上已经写着「热歌榜」，工具栏里又写一遍。改成 `已显示 N 首`，
右侧补上曲库规模（`670,304 首 · 135,952 位歌手`）—— 信息没丢，重复没了。

### 3. ⚠️ 换片源时会用**上一个文件**的音轨表判"音轨型/声道型"（真 bug）

mpv 的 `observe_property` 推的是"变化后的值"。`loadfile` 之后、mpv 把新片源的
`track-list` 推过来之前，`observed(trackList)` **还是上一个文件的列表**。

而轮询里是这么判策略的：

```js
if (status.tracks.length > 0 && this._strategy === 'channel' && !this._trackMap) {
  this.resolveStrategy();          // ← 用的是上一首的音轨表
  if (this._strategy !== before) this._applyVocalMode();
}
```

上一首是双音轨片源 → 判定成"音轨型"并写进 `_trackMap`；
等新片源的真实音轨表到了，`_strategy` 已经是 `'track'`、`_trackMap` 也有了，
**这个条件再也不成立** → 判错了永远不会纠正。

后果：单音轨（左右声道型）的片子被当成音轨型 →
**点「伴唱」没反应**（它去切不存在的音轨 2，而不是切声道）。

修法：片源没 `file-loaded` 之前不认那份音轨表：

```js
this._trackList = this._loaded ? (this.ipc.observed(OBS.trackList) || []) : [];
```

这个是**冒烟测试偶发失败**暴露出来的（`识别为声道型片源 - tracks=2`），
查下去才发现不是测试的问题。顺手把测试里两处"固定 sleep / 只等 >=1"改成
轮询等确定状态，连跑 3 次全过。

## 三、整体页面评审：还剩什么可以优化

按"收益 / 改动量"排：

### 已经做了的

| 项 | 收益 |
|---|---|
| 分页条移出滚动区 | 不再遮内容（用户直接反馈的问题） |
| 图例并入底栏 | 省 31px |
| 状态行按需显示 | 省 22px |
| 数据源/分段控件边距收紧 | 省 8px |
| 去掉重复的页签标题 | 信息密度 |
| 空闲占位提示 | 不再是一块黑 |
| 换片源音轨表竞态 | 点伴唱没反应的真 bug |
| 控制条：音量/快进快退任何宽度都保留 | 上一轮的问题 |
| 歌名写进窗口标题 | 窄窗口下也知道在播什么 |

### 第二轮：上面 7 条建议全部落地

| # | 建议 | 做法 | 结果 |
|---|---|---|---|
| 1 | 右侧面板层级偏多 | **数据源切换挪到顶栏**（一行小分段控件） | 右栏顶部省 **44px** |
| 2 | 右栏 460px 偏宽 | `minmax(360px,460px)` → `minmax(340px,400px)` | 左栏 770 → **830**，16:9 画面大 **8%** |
| 3 | 「下首」每行都占 46px | 默认 `opacity:0`，行 hover / `:focus-within` 才出现 | 歌名多 **46px**；键盘 Tab 仍能聚焦到它 |
| 4 | 三个圆点只靠颜色 | 形状也给一个维度：本地=实心圆、在线=空心环、不可播=小方 | 色弱可辨 |
| 5 | 搜索框没有清空 | 加了 ✕ 按钮（有词时才出现），清完回到该页签默认内容 | 遥控器不用一路退格 |
| 6 | 图标按钮缺 aria-label | ⏪⏩ ♭♯ ⚙ ♡★ 分页 ‹›«» 全补上 | 读屏可用 |
| 7 | 变调在窄窗口会隐藏 | **全屏让位**：全屏只在最宽档（F / Esc / 双击画面都在），变调保到 ≥570px | 1136 宽窗口下变调仍在，进度条还有 139px |

实测（三档宽度）：

| 控制条宽 | 档位 | 显示 |
|---|---|---|
| 830（窗口 1266） | w0/w1 | 全部（含立体声、变调、全屏） |
| 700（窗口 1136） | w2 | ⏪ ⏸ ⏩ 切歌 · 进度 · 伴唱/原唱/词 · **变调** · 音量（全屏让位） |
| <570 | w3 | 再藏变调（`[` `]` 快捷键仍在） |

### 更早一轮评审里已经做完的


1. **右侧面板的层级仍然偏多**：数据源(44) + 分区页签(37) + 曲库页签(40) + 工具栏(36)
   = 157px，列表只剩 ~400px。可选：
   - 把"数据源"收成一行小控件（省 ~14px）；
   - 或者把"数据源"挪到顶栏（省 44px，但它就离开了你要求的位置）。
2. **右侧面板 460px 偏宽**：`minmax(360px, 460px)`。收窄到 400px，视频宽度
   从 770 → 830（**画面大 8%**）。代价是列表里歌名可用宽度少 60px。
3. **列表行里的「下首」每行都显示**，占 ~50px。改成 hover 才出现，歌名能多 50px。
4. **色弱友好**：本地/在线/不可播 三个圆点只有颜色差异，可以再加形状差异。
5. **搜索框没有"清空"按钮**（遥控器场景尤其需要）。
6. **图标按钮缺 `aria-label`**（现在只有 `title`）。
7. **变调在 730px 以下会隐藏**（有 `[` `]` 快捷键）。这是空间不够的取舍，
   不是 bug；要它一直在的话，得砍掉「全屏」按钮。

## 四、歌手页重做 + 主题系统

### 4.1 歌手展示（用户："好难看"）

量出来三个问题：

| 问题 | 原因 | 实测 |
|---|---|---|
| **A-Z 索引被压成一条细带** | `overflow-x:auto` + `min-width:22px`，26 个字母要 648px，右栏只有 ~380px | 只露出 A~O，底下还挂一根横向滚动条 |
| **"热度 2147483647"** | 曲库里歌手热度大量是 `INT32_MAX`（哨兵值） | 数字又长又没意义，还特别扎眼 |
| **"地区/类型"两个下拉被裁掉** | 工具栏 `flex-wrap: nowrap`，四件东西一行放不下 | 最后一个下拉只露出半截 |

改法：

- **A-Z 改换行排布**（`flex-wrap: wrap` + 20×22px 的小按钮）→ 两行放下全部 27 个（A-Z + #），一眼看全，没有滚动条。
- **删掉热度**，地区/类型改成两个**小胶囊**（`.chip`）。
- **头像 38 → 44**，名字加粗到 15px/600，右侧加一个 `›` 提示可点进去。
- **没头像的歌手**用**名字算出来的渐变色**兜底（`avatarTint()`：名字 → 稳定色相），
  比统一的灰底字母好看，一屏里也能靠颜色快速区分。
- **工具栏允许换行**，并把两个下拉**包成一组**（`.filters`）——
  整组换行，不会出现"一个下拉孤零零留在第二行"。

实测：行高 55 → 61，列表 376px（约 6 行）；A-Z 62px 两行；工具栏 101px（搜索一行 + 筛选一行）。

### 4.2 主题系统

原来颜色是**散落在各个组件里的 52 个硬编码色值** —— 换主题只会换一半。

现在：

1. `styles.css` 里定义了一整套语义变量（`--bg/--panel/--panel-2/--panel-3`、
   `--line/--line-2`、`--text/--text-2/--dim/--dim-2`、`--focus*`、`--row-*`、
   `--btn*`、`--gold*`、`--accent*`、`--online*`、`--scroll`），
   **77 处硬编码色值全部替换成变量**（脚本批量替换，替换后只剩 1 处 `#ffffff` 是有意的）。
2. 主题 = `<html data-theme="...">` 上的一套变量覆盖。四个主题：

| 主题 | 底色 | 主色 | 场景 |
|---|---|---|---|
| **暗夜**（默认） | #0b1016 | 青绿 #27cca4 | 原来的配色 |
| **午夜蓝** | #070b14 | 青蓝 #58b6ff | 更深更冷 |
| **暖棕** | #14100c | 琥珀 #f0a63c | 包厢暖色调 |
| **浅色** | #eef2f7 | 绿 #0f9d7c | 白天 / 亮房间（`color-scheme: light`） |

3. 设置页有主题选择器（每个按钮带一个小色块预览），**点一下立即生效**。
4. **不闪**：主题存两份 —— 设置文件（权威）+ `localStorage`（同步读）。
   `main.js` 在 `createApp().mount()` **之前**就把 `data-theme` 贴上，
   不会先渲染一帧默认配色再切过去。

## 五、第三轮界面收敛（2026-09）

用户反馈：“页面样式还能怎么优化”。这一轮不改交互模型，只处理视觉层级和密度。

### 5.1 右侧主分区

- 去掉外框 + 等宽填充按钮的“厚重分段控件”
- 改为轻量导航：选中态浅色底 + 短下划线 + 计数徽标
- 与下面曲库二级页签仍然区分，但不再像两排同样的按钮

### 5.2 歌曲列表

- 从“每行一张小卡片”改成连续列表行
- 选中/播放中只用一条左侧色条 + 浅背景表达状态
- 收藏、下首等次要操作默认透明，悬停才强化
- 在线封面缺失时也使用名字渐变色 + 首字，不再出现空白灰块

### 5.3 歌手页响应式网格

- 歌手列表改为 `repeat(auto-fill, minmax(138px, 1fr))` 网格
- 1180×720：右栏 400px，稳定两列
- 1440×820：右栏增长到约 456px，实测三列
- A-Z 索引强制横跨全部列，不会被当成一张歌手卡
- 窄栏优先保留地区标签；歌曲、在线结果、本地文件仍保持单列

### 5.4 工具栏与分页

- 搜索框加搜索图标、聚焦光圈、独立清空按钮
- 分页条与图例分成左右两组，页码控件包进一个紧凑容器
- 窄栏自动隐藏“每页”文字，但保留每页条数和翻页功能
- 显式分页、页码跳转、PgUp/PgDn、每页条数均未改变

### 5.5 图标与播放控制

- 新增统一 SVG 图标：播放、快进快退、收藏、上下移动、删除、关闭
- 控制条分组之间加细分隔线；窄档位自动去掉分隔线
- 播放/暂停、切歌、进度、快进快退、原伴唱、音量在任何宽度都保留

### 5.6 实拍验证

- 1180×720：所有控制不换行，右栏 7 行可见，分页不遮内容
- 1100×700（窗口最小尺寸）：控制条仍在一行，曲库 8 行可见
- 搜索页、设置页、已点页、歌手页分别实拍检查，未发现溢出或遮挡
- 1440×820 歌手页实测三列；页面无横向滚动
- `npm run build:web` 通过；全量测试在改动前基线全绿，改动后再次回归
