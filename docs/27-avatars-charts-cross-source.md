# 27. 歌手头像、统计图表、在线歌入歌单、标签重做

> 五项：右侧标签重做、歌手头像、播放统计图表、在线歌加入歌单、封面改 hover 才查。

## 1. 右侧标签重做（原来两排长得一样）

原来上下两排标签**视觉上几乎相同**（都是圆角填充按钮），看不出层级：

```
[曲库] [已点 3] [已唱 4] [收藏 2] [歌单 1]      ← 分区
[热歌榜] [搜索] [在线] [歌手] [本地文件]        ← 曲库内的分类
```

改成两种**刻意不同**的样式：

| 层 | 样式 |
|---|---|
| **分区**（曲库/已点/已唱/收藏/歌单） | **分段控件** —— 一个圆角容器装着，等宽，选中填充绿色 |
| **分类**（热歌榜/搜索/在线/歌手/本地文件） | **下划线标签** —— 扁平，选中变色 + 绿色下划线 |

层级一眼就分得出来。

## 2. 歌手头像

曲库里 `singers.image` 存的是**文件名**（`ip1_singer_image_1030`），不是 URL。
地址规则参考 maidong 的 `MuseDatabase.resolveSingerImageUrl()`：

```
CDN 前缀（global_confs.cdn_path，默认 https://pub.mcdn.cherryonline.cn/）
  + 文件名 + ?imageView2/1/w/100/h/100/q/95!/format/webp
```

### 踩到的两个坑

**① `trimEnd('/')` 在 V8 里是空操作**

```js
'https://a.cn/'.trimEnd('/')   // => 'https://a.cn/'  （没去掉！）
```

ES 规范里 `trimEnd` **不接受参数**，传进去的 `'/'` 被忽略（只裁空白）。
于是拼出了 `https://cdn//ip1_...` 这种双斜杠地址。改用 `replace(/\/+$/, '')`。

> 全项目搜了一遍，只有这一处这么写。

**② 不能无条件追加七牛参数**

maidong 是给所有 URL 都加 `?imageView2/...`（它的 image 只可能是自家文件名）。
但我们已经支持完整 URL 了 —— 给非自家 CDN 的地址加七牛参数会直接 404。
所以改成：**文件名才拼 CDN + 参数，完整 URL 原样返回**。

界面上是**圆形**头像（和歌曲封面的方形区分开），没有头像时显示歌手名首字。

## 4. 在线歌加入歌单

歌单原来只存**曲库 id**。在线歌不在曲库里，所以约定：

```
1. 加歌单时先把元数据存进「在线收藏」（否则以后没法按 id 还原歌名）
2. 歌单里存合成 id  "online:<platform>:<id>"
3. 渲染时按前缀分流：online: 开头查在线收藏，其余走曲库批量查
```

`QueuePanel.loadSongs()` 现在两种 id 都能还原，并且**保持传入顺序**。
在线结果的右键菜单多了「加入歌单」，选择弹窗里会标一个「在线」角标。

## 5. 封面改成 hover 才查

原来是整页预取（30 首 = 30 次请求）。改成：

- **首屏前 12 行**立即查（可见区域不会空着）
- **其余等鼠标移上去再查**

大部分"用户根本没看"的请求就省掉了。设置开关也改成**启动时读一次**缓存住，
不再每次 hover 都走一次 IPC。

## 顺带修掉的：冒烟测试会清掉用户的已唱/收藏/歌单

`npm run smoke` 跑在**真实状态文件**上，里面会 `clearHistory()`、动收藏和歌单。
之前只快照还原了队列，结果**每次跑 `npm test` 都会把用户的已唱记录清空**。

现在四样（队列/已唱/收藏/歌单）全部快照还原，并且加了断言防止再次静默失效。

> 还原时还踩了一下：`history` 里的字段是 `songId`（不是 `id`），
> 直接丢给 `markPlayed()` 会因为 `song.id === undefined` 而**静默不还原**。
