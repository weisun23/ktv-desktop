# 界面改版：左右布局、双击/右键、已点去重

**日期**：2026-09-22

## 1. 布局改为左右分栏

```
┌───────────────────────────┬──────────────────┐
│                           │  曲库 / 已点      │
│         视频画面           │  已唱 / 收藏      │
│                           │  歌单             │
├───────────────────────────┤                  │
│  播放控制条（横向）         │                  │
└───────────────────────────┴──────────────────┘
```

左栏只有画面 + 紧贴其下的控制条，右栏放全部功能（搜索、曲库、队列、收藏、歌单）。

### 为什么控制条不能叠在画面上

libVLC 渲染在**原生 Win32 子窗口**里（见 `docs/00-architecture.md` §6），
HTML 元素**无法叠加在它上面**。所以"控制条浮在画面底部"在当前架构下做不到，
要做需要改成双原生窗口。

现在的做法是**控制条紧贴画面下方**，视觉上等同于"画面底部的控制栏"，
且不用引入层级问题。

## 2. 单击选中、双击点歌、右键菜单

| 操作 | 行为 |
|---|---|
| 单击 | 选中（蓝框高亮） |
| 双击 | 点歌 |
| 右键 | 弹出菜单 |

右键菜单项：点歌 / 下一首播放 / 收藏 / 加入歌单 / 复制歌名。
已在已点列表里的歌，"点歌"和"下一首播放"会**置灰禁用**。

已点、已唱、收藏、歌单里的条目也都支持右键。

## 3. 已点的歌不能重复点（并修了队列模型）

### 问题

原来 `addToQueue` 允许同一首歌重复入队，而且唱完的歌只是把状态标成 `played`
**留在队列里**。结果是：

- "已点"列表越滚越长
- 同一首歌可以点很多次，列表里出现多条
- 去重校验也无从下手（因为队列里本来就允许重复）

### 修复

**改数据模型**：唱完的歌**移出队列**，进入已唱历史。

```js
// 之前：标成 played 留在队列里
takeNext() {
  const current = queue.find(q => q.status === 'playing');
  if (current) current.status = 'played';   // ← 留在列表里
  ...
}

// 现在：直接移出
takeNext() {
  this.data.queue = this.data.queue.filter(q => q.status !== 'playing');
  ...
}
```

**加入去重**：

```js
addToQueue(song) {
  const existing = this.data.queue.find(q =>
    q.songId === song.id && (q.status === 'waiting' || q.status === 'playing'));
  if (existing) return { entry: null, duplicate: true, existing };
  ...
}
```

所以：

- 已在**已点**里的歌 → 点歌被拒绝，提示"已经在已点列表里了"
- 唱完的歌 → 已移出队列，**可以再点**（符合"除非当前播放完毕"的要求）

界面上：曲库列表里已点的歌会显示"已点"徽标，`下首` 按钮置灰，
右键菜单对应项禁用。

## 4. 窄栏下的行布局

改成左右布局后右栏只有 460px。原来的多列 grid 出问题了：

```css
/* 固定列 200+64+72+操作 ≈ 400px，加间距超过可用宽度 */
grid-template-columns: 1fr 200px 64px 72px auto;   /* ← 1fr 被挤成 0，歌名看不见 */
```

`1fr` 列被挤成 0 宽度，**歌名整列消失**（截图里每行左侧空白）。

改成两行式 flex 布局：

```
● 歌名                    ♡  下首
  歌手 · 语种 · 声道2
```

```css
.song { display: flex; align-items: center; gap: 9px; }
.info { flex: 1; min-width: 0; }   /* min-width:0 是关键，否则内容不肯收缩 */
```

窄栏里这种布局比多列 grid 稳定得多。

## 5. 一个测量教训（第二次）

改完布局后截图看，右栏被切掉了，我一度以为是布局 bug。量了 DOM 才发现
`main` 是 1266px、分栏 `770px + 460px`，**布局完全正确**。

真正的问题是**截图脚本不是 DPI-aware**：

```
显示器 scaleFactor : 1.5        ← 150% 缩放
物理分辨率         : 1920x1200
逻辑分辨率         : 1280x800
```

PowerShell 截图脚本没声明 DPI 感知，只拿到逻辑坐标 1280x800，
于是**只截到了物理屏幕的左上 2/3**。窗口真实尺寸是 1920x1200。

修法：截图前声明 DPI 感知。

```powershell
[DpiAware]::SetProcessDpiAwarenessContext([IntPtr](-4))
```

> 这是本项目第二次被测量工具误导（第一次是 `getTime()` 的 300ms 上报粒度）。
> **性能/布局诊断前，先确认测量工具本身的精度和坐标系。**
